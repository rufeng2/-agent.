# 架构说明

## Agent 层

`HybridEcommerceAgent` 使用 DeepSeek 生成 `AgentPlan`。Pydantic 将工具限定为注册表中的 10 个工具，并限制最多 6 步。计划校验失败、模型超时或未配置 Key 时进入确定性降级。模型总结只能读取工具结果，指标和风险等级不能由模型覆盖。

## 分析层

固定种子生成 90 天数据。纯 Python 模块负责 GMV 归因、漏斗、ABC、RFM、活动效果、竞品价格与预测。工具统一返回指标、证据、摘要和警告，活动收益明确标记为模拟测算。

## 持久化层

开发环境默认 SQLite，生产通过 `ECOMMERCE_DATABASE_URL` 使用 PostgreSQL。SQLAlchemy 仓储保存会话、消息、运行记录、工具执行、建议、审批审计和 Agent 评测。审批使用版本号与幂等键避免重复或过期操作。

## API 与前端

FastAPI 同时提供同步分析和 SSE 事件流。Vue 工作台展示会话、执行模式、证据、审批、运行指标和评测结果。运营知识库继续提供规则与 SOP 检索，但属于辅助模块。

## 失败策略

- LLM 失败：确定性降级并记录原因。
- 工具失败：保留已有证据并返回警告。
- 数据库失败：不伪造持久化成功，高风险动作保持关闭。
- 非法计划：拒绝未知工具、任意 SQL 和超过 6 步的计划。

## 验证

pytest 覆盖算法、Agent、API、持久化、评测和性能；Playwright 覆盖桌面与移动核心流程。离线 Agent 评测默认不访问 DeepSeek，`--online` 才执行真实模型评测。
